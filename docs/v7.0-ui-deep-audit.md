## 1. 上一版尚未解决的结构问题

第一版完成了布局和静态视觉统一，没有建立全局动效、材质、浮层和渲染调度体系。具体证据：

- `src/styles/workspace.css:145` 为普通任务卡显式关闭 backdrop-filter；设置卡也使用实色。这控制了视觉噪声，但玻璃目前主要集中在弹窗。
- `src/components/LiquidGlassRuntime.tsx:63` 与 `:91` 用 feTurbulence 生成折射场，再做位移和 RGB 分离。当前折射场来自噪声，尚未统一建模容器轮廓、边缘法线和高光。
- `src/styles/liquidGlassDialogs.css:24` 将 backdrop-filter 也加入过渡，具体渲染成本需在 WebView2 测量。
- 主样式、新工作区、弹窗玻璃与三个主题文件共约 2153 行、75 处 `!important`。这是样式叠加与覆盖的维护信号，不能据此断言运行慢。
- `src/App.tsx:17`、`src/components/Layout.tsx:26`、`src/components/UsageButton.tsx:8` 仍有全 Store 订阅。订阅范围与视觉更新范围未完全分开；React 重新执行也不等于 DOM 必然全部更新。
- `src/components/settings/ParameterSlider.tsx:18` 的每次滑动变化进入 `setLiquidGlass`；后者每次安排一个串行保存。串行保证顺序，不等于合并了高频保存。
- `src/pages/Home.tsx:77` 在滚动事件中更新 React 状态；虚拟列表已有，但可以评估按可见区变化更新，而不是每次滚动位置变化都重算。
- `src/components/CelebrationAnimation.tsx` 的完成反馈仍以中心浮层与粒子为主；`ZenMode.tsx` 有 saving/exiting 阶段，但最低等待、退场与全局完成锁需要复审。

## 3. 关键动效的具体定义

以下时间只是原型起点，最终以操作体验和帧时间验证，不机械照搬上游时长。

### 完成待办

触发 → 勾选立即响应 → 保存结果反馈 → 行退出/归档 → 其他行补位 → 概览更新。

- 交互状态必须跟随保存结果。保存失败时保留或恢复条目，提供明确错误反馈。
- 只对真实消失的任务做退出；“全部”中保留已完成任务时，应展示状态变化与必要的重排。
- 普通完成使用行内反馈，全部完成可以有可选、短暂的里程碑反馈。
- 使用每任务 pending，防止同一任务重复提交；不必用全局锁阻止用户继续完成其他任务。
- 降低动态效果时仍保留清晰的完成状态，不要求等待一整段转圈或飞出。
- 虚拟列表采用可见行的位置动画，或者改为测量实际高度；单独动画 DOM 高度会与当前固定行高计算冲突。

### 导航、筛选与详情

- 选中指示块说明当前位置变化；内容短淡入帮助识别切换，避免所有内容每次重新排队登场。
- 快速连点以最后一次意图为准，取消过时的动画完成回调。
- 详情进入/返回保留关联任务位置与原列表滚动。宽窗侧栏与窄窗详情共用同一任务状态。
- 过滤大量任务时直接稳定更新，限制逐行入场数量。

### 统计、配置与浮层

- 折叠同时处理布局占位、内容淡出和节点移除，结束时不留空隙，不让已退出控件继续获得焦点。
- 浮层统一遮罩、焦点、Esc、返回、层级和滚动锁定；菜单、警告对话框和详情侧栏保留各自语义。
- 主要运动优先用 transform/opacity；必要的高度变化限定到小区域。它们并不保证浏览器一定走合成层，仍要检查实际帧轨迹。

## 4. 玻璃方案：先材质体系，再评估渲染引擎

推荐先建立拟议的 `Surface` / `GlassSurface` / `OverlayHost`，统一裁切轮廓、前景文字层、背板、边缘高光、外阴影和颜色语义。拟议名称代表未来接口，目前尚未创建这些组件。

建议应用范围：窄窗导航、宽窗侧栏、常用菜单和弹窗，以及必要的悬浮控件。任务列表优先可读和高密度，不让每一行都承担完整折射、模糊、色散叠加。保留用户熟悉的中性背景。

玻璃实现分三档：

1. 实色：减少透明、硬件不适合或高对比需求时使用。
2. 常规：基础模糊、统一 tint、边缘层次，有限的形状相关折射。
3. 增强：边缘法线折射与有限色散，先在单个小面积组件中验证，再决定扩展。

上游的 LiquidGlass、capture 与 shader 三个文件合计约 3400 行，包含纹理捕获、层级、图集、降采样、复用及资源释放。Flutter 可在其渲染层中实现这些机制；在 React DOM / WebView2 中需要重新解决背景来源和合成接入，不应直接承诺照搬后同等性能。

保留 CSS/SVG 路线作为常规档。只有实际对比证明不满足效果，再做增强渲染实验。不要每帧截整个 DOM，不要把所有文字和输入控件一并栅格化；基础 backdrop-filter 支持也不能替代对 SVG URL 滤镜实际效果的验证。

## 5. 性能改进候选与边界

| 当前信号 | 建议 | 如何验证 |
| --- | --- | --- |
| App/Layout/部分工具栏订阅整个 Store | 缩小 selector；倒计时文本独立订阅；使用稳定的动作引用 | React Profiler 比较一次倒计时 tick、一次设置拖动触发的组件执行范围与时间 |
| 玻璃参数每次变化都进入保存队列 | 瞬时预览本地更新，按帧合并视觉更新；释放时提交；键盘操作也提交，必要时有有界 debounce 和最终 flush | 连续拖动时统计 IPC/JSON 写入次数；最后参数与重启后的值一致；失败可恢复 |
| 滚动逐次 setScrollTop | 评估按帧、可见索引范围变化更新；缓存不变的派生结果，保留真实虚拟化 | 100/1000 任务时滚动提交次数、长帧、锚点、编辑行和日期弹层位置 |
| 多处周期刷新 | 统一视觉刷新调度；托盘隐藏时停止无用的预览、粒子和视觉刷新 | 对比显示/隐藏期间的工作量；恢复时 UI 正确；不单凭失焦判断隐藏 |
| 番茄钟按每次 tick 减 1 | 若实施后台暂停，先建立基于截止时间/已累计时间的业务计时，避免依赖定时器按时执行 | 隐藏、休眠、恢复、暂停和跨天场景；不得因为视觉省电让计时出错 |
| 当前全局色彩/transition-all/!important 叠加 | 抽取语义变量与组件样式，明确属性和覆盖边界；区分维护收益与运行时收益 | 比较主题一致性、真实样式计算/绘制记录；不以删除行数冒充加速 |
| 玻璃多层重复处理 | 限制面积和层数；分级降采样、背景不变时复用、结束释放；浏览器实现单独验证 | 静止、滚动、拖动和弹层叠加时记录合成/绘制、内存；不能只看 React commit |

托盘机制用户已验证，后续性能重构应保留其生命周期与恢复逻辑，避免以暂停渲染为名破坏窗口显示或业务计时。

## 6. 实施顺序与交付物

1. 基线与拆分：记录 0/100/1000 任务、400/550/1040 宽度、三种主题、玻璃开关、显示/托盘隐藏、100%/150% DPI。先缩小订阅与参数更新范围。
2. 共用基础件：动效策略、按压反馈、选中指示、可中断展开/退出、材质角色及浮层宿主；清理这些基础件覆盖到的旧样式，不再无休止添加覆盖层。
3. 两条完整流程试点：待办完成与重排；设置展开、主题/玻璃预览和保存。交付可比较的常规/增强玻璃样例与性能记录。
4. 再铺页面：详情、新建、日历、统计共享基础件；明确宽窄窗形态，保留焦点与滚动状态。
5. 验收：用户快速连续操作、保存失败、降动效、减少透明、后台恢复、资源释放和托盘兼容；核对既有失败，不跳过测试。

拟议性能目标：在选定 60Hz 参考设备上用 16.7ms 帧预算观察典型动效，记录 P95 帧时间、长任务、输入响应、IPC/写盘、JS/进程内存与隐藏状态工作量。这里没有实测基线，暂不承诺百分比提升；增强玻璃若明显恶化帧时间或可读性，应降低质量或缩小应用范围。
