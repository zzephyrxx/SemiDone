# 全局玻璃与顶部菜单修复

日期：2026-10-26；分支 `codex/v7.0`。本轮前端修改未提交推送。

## 定位结果

1. 浏览器诊断读到 `prefers-reduced-transparency: reduce = true`。上一轮 `ui.css` 在该条件下把导航的伪元素和普通卡片设为不透明背景、`backdrop-filter: none`，即使用户开启应用内玻璃也会生效。正常的关闭和公告弹窗没有这条减少透明度覆盖，因此表现不同。
2. 普通卡片只使用 blur / saturation，没有接入已有弹窗的折射、色散滤镜。顶部标题栏也未接入该材质。
3. 新 Surface 把背景滤镜放在伪元素中，与正常弹窗的实际元素绘制路径不同；其局部 SVG 定义位于过滤元素内部。本轮将滤镜放回实际表面，局部定义通过 portal 放到 body，避免依赖被过滤元素内部的资源。

初次浏览器诊断同时读到其 iframe 的玻璃总开关为关闭状态，故该采样只能证明系统偏好和当时的计算样式，不能单独作为“显式开启后也失效”的视觉证据。媒体规则的覆盖条件通过源码核实，并在新增回归中模拟。后续建立了独立、默认开启玻璃的测试夹具，不改写真实应用的设置或任务。

## 修复

- 使用 `liquidGlassBackdrop` 统一全局表面、导航与预览的折射、色散、模糊参数。
- 用单独的 `liquidGlassSurfaces.css` 统一材质，移除 `ui.css` 中互相竞争的背景和自动禁用规则。
- 任务、设置、概览、设置条目、顶部标题栏接入完整滤镜链；悬浮导航及选中块直接在实际元素绘制玻璃，并保留按尺寸生成的局部滤镜。
- 应用内显式开启玻璃时，不因系统“减少透明度”自动变回实色；没有修改 Windows 设置。强制颜色模式继续使用系统颜色，高对比度提高填充对比；不支持 backdrop-filter 时仍提供回退。
- 总开关关闭时明确移除滤镜。折射为零时去掉 SVG URL，避免引用已经卸载的局部定义。
- 保留原有关闭、公告弹窗的材质样式与业务逻辑。

## 验证

后续人工反馈：用户已确认“顶部菜单和卡片都已恢复”，确认该轮玻璃修复生效；不代表已完成所有窗口模式、DPI 或 GPU 性能验证。

- 新增 3 项样式/组件回归：模拟减少透明度时导航、标题栏及卡片仍使用共享滤镜；局部 SVG 定义在表面外且卸载后清理；模糊/色散/折射与总开关的联动。
- 全套前端测试 180 项，176 通过，剩余仍是原有 4 项打赏相关失败。未删除或跳过这些用例。
- TypeScript、改动文件定向 ESLint、Vite 生产构建通过。既有的主包大小、混合导入、Browserslist 警告仍在。
- CSS 回归使用真实样式表，并显式展开所测试的媒体条件；jsdom 不实际绘制 GPU 滤镜，不等同于视觉或帧率验证。
- 计算样式诊断已能通过原生可访问性树读取；后续刷新操作报 `coordinate input geometry is unavailable`，窗口激活也失败，新增隔离页打开请求为 queued。因此未确认修复后的实际截图或 GPU 合成结果，仍需目视反馈。
