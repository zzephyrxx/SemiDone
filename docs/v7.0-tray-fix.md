# v7.0 关闭到托盘修复

日期：2026-10-26。分支：`codex/v7.0`。按用户约定于北京时间 01:05 后执行，先推送 UI 原型提交 `f349911f`，再处理此修复。

## 根因与改动

原右上角关闭按钮先弹出退出确认，确认后直接调用 `exit_app` → `app.exit(0)`。它绕过 Rust 已有的 `WindowEvent::CloseRequested` 隐藏处理，结束进程并销毁窗口与托盘；之后的“显示窗口”当然无法恢复该进程里的窗口。单纯修改 native close handler 无法改变这个前端退出路径。

现在默认走 `close_main_window` 命令发送原生关闭请求，Rust 按保存的 `closeToTray` 设置处理。开启时先阻止窗口销毁，再隐藏现有窗口；关闭时使用正常退出路径。设置页提供“关闭到托盘”开关，首次使用和旧配置缺字段时均默认开启，明确保存的 false 会保留。设置仅在持久化成功后更新 native 关闭策略；清空设置后同步恢复默认值。浏览器预览不会尝试关闭浏览器或假装支持系统托盘。

完整、条状、悬浮球和 Zen 共享同一关闭入口。默认关闭到托盘时不先改变窗口形态，恢复后继续保留当前形态。关闭该选项后，自定义叉号仍弹出完整退出确认；系统 Alt+F4 则走原生关闭。托盘“退出”始终显式退出应用。

同时移除了 `Focused(true)` 对“用户主动隐藏”标记的无条件清除，避免隐藏过程中迟到的焦点事件重新启动置顶守护。只有显式的托盘恢复才释放隐藏状态。恢复依次解除最小化、显示、恢复用户置顶状态并聚焦；错误和窗口不存在均写入日志。左击托盘直接恢复，右击显示菜单，避免左击菜单与恢复动作竞争。
