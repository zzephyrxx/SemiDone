## 已确认的交互

- 导航跟手，松手后切页；普通点击和键盘激活继续可用。
- 完成任务退出当前列表，只在“已完成”筛选查看，不增加底部完成分组。
- 加入导航按压轻微伸展/回弹、弹窗进入/退出、页面短暂过渡、任务列表补位及排序移动。未额外改造设置展开效果。
- 系统优先级补充回答为“以应用开关为准，开启就播放”。应用默认开启；没有修改 Windows 系统设置。

## 原实现的问题与修复

| 部分 | 原问题 | 本轮行为 |
| --- | --- | --- |
| 导航 | 只测量当前路由并设置 CSS 变量，没有拖动事件 | Pointer Capture 跟踪指针；按帧合并滑块绘制，松手选择最近项，轻微越界阻尼；横向顶部及纵向侧栏共用；支持取消、失去捕获、窗口失焦及 Esc 恢复选中项 |
| 任务完成 | 同时淡出并移动 36px，固定定时器可能早于浏览器绘制结束；已完成任务仍可能出现在全部列表 | 约 110ms 淡化到 .55，然后向右滑出整个可视范围，总时长 420ms；正常由 animationend 触发移除，500ms 定时器仅作兜底；退场后补位 |
| 任务去向 | 全部列表混入已完成项，今日列表也可能显示已完成项 | 活跃筛选排除已完成项，完成记录保留在底层数据，只在“已完成”列表显示；今日到期统计同步按未完成项计算 |
| 列表补位 | 尺寸测量无条件清掉旧位置，无法建立平滑移动的起点 | 仅真正滚动时清理；保留原位置，使用 WAAPI 对可见卡片执行 240ms 位移；继续保留虚拟化及批量更新保护 |
| 弹窗 | 关闭直接卸载，退出动画没有存活时间 | 统一保留退出阶段：进入 180ms、退出 150ms，淡入淡出和小幅位移缩放；关闭中不可交互，退出结束才释放；支持退出中重新打开及关闭动效时立即收尾 |
| 页面 | 没有统一的路由过渡 | 新页面 180ms 淡入；不保留旧页面的交互副本，页内状态变化不反复触发 |
| 全局开关 | JS 根据系统偏好关闭；工作区另有“减少动效”的全局 !important 覆盖 | JS 和 CSS 均服从应用开关。关闭会取消动画并立即完成退出；开启不被系统偏好静默覆盖；Zen 模式也使用相同开关 |

弹窗接入范围：新建待办、关闭确认、删除确认、欢迎公告、用户资料、清除缓存、报表导出、数据目录和使用详情。确认按钮的业务操作仍按原生命周期执行；不会为装饰动画延迟进程退出、文件导出或数据操作。

导航滑块保留此前的中性玻璃底板，没有浅蓝色填充；色散保持约 8px 平滑过渡，基础折射仍限于更窄边缘，不恢复固定彩色描边。

## 验证

- TypeScript、改动文件定向 ESLint、Vite 生产构建通过。保留既有包大小、混合导入、Browserslist 数据过期提示。
- 全套 205 项，201 通过；4 项仍是既有打赏功能失败，没有删除或跳过这些用例。报告：`docs/ui-motion-implementation-test-results.json`。
- 新增 11 项回归：横向/纵向拖动、拖动不切页及松手切页、指针取消/捕获丢失、Esc 与键盘、紧凑模式返回及帧清理；弹窗退出保留、重开不丢输入、关闭动效时取消动画；页面切换与页内状态更新；系统减少动效时应用开关仍控制 JS 和实际样式表。
- 现有用例增加了完成任务退场/记录保留、真实 animationend 事件处理、兜底收尾、尺寸测量后仍能补位及排序的检查。jsdom 缺少 AnimationEvent，React 在该测试环境使用 WebKit 事件名；测试按其实际注册名称派发事件，生产浏览器仍使用标准事件。
- 可见列表仍保持虚拟化；导航测试确认密集 pointermove 不引发 React 提交，只合并为一次帧绘制。这不等于已测得 WebView2 的帧率。
- 开发服务器正常返回关键模块，未发现此前的空模块响应。

## 实际视觉验证边界

当前工具仍无法刷新或截图现有浏览器预览：原生点击报 `coordinate input geometry is unavailable`，独立 Chrome 控制也不可用。没有通过其他技术绕过该限制，因此本轮未完成真实鼠标拖动、动画帧、Windows WebView2、DPI 或透明桌面背景的人工观感验证；不能将上述 DOM/样式/事件回归当作视觉验收。

刷新 [v7 预览](http://127.0.0.1:5177/v7-preview.html) 后，可见应用动效有效状态及系统偏好。手工完成任务会记录浏览器的 `ui-task-exit` 开始和结束事件，拖动导航会显示跟手/松手状态；这些提示只观察操作，不自动创建、完成或删除真实任务。
